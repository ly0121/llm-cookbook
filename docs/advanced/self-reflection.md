# LLM 自我反思（Self-Reflection）

LLM 在"评价"模式下比"生成"模式更准确。通过让模型审视自身输出，可以实现迭代改进。

## 1. 为什么一次生成不够

| 现象 | 原因 |
|------|------|
| 质量不稳定 | 采样随机性 |
| 逻辑不连贯 | 自回归前文锁死后文 |
| 遗漏关键点 | 注意力分配不均 |
| 事实错误 | 幻觉 |

**核心洞察：** 同一个 LLM，扮演"作者"和"审稿人"两个角色，能产生自我改进效果。

## 2. Reflexion 框架

```
生成初稿 → 自我评估 → 发现问题 → 修改 → 再评估 → ... → 满意 → 定稿

对应心理学：
  系统1（快思考）→ LLM 单次生成
  系统2（慢思考）→ LLM 自我反思
```

## 3. 迭代改进循环

```python
MAX_ITERATIONS = 3

draft = generate(prompt)
for i in range(MAX_ITERATIONS):
    critique = evaluate(draft)  # LLM 评估自身输出
    if critique.score >= 4:
        break  # 满意，停止
    draft = revise(draft, critique.feedback)  # 根据反馈修改
```

## 4. 反思提示设计

```python
evaluate_prompt = """作为严格的审稿专家，评估以下文章：

文章：{draft}

请从以下维度评分(1-5)并给出具体修改建议：
1. 准确性：事实是否正确
2. 完整性：是否遗漏关键点
3. 逻辑性：论述是否连贯
4. 可读性：表达是否清晰

输出格式：
总分: X/5
问题: [具体问题列表]
建议: [具体修改建议]"""
```

## 5. 多 Agent 互评

```
Agent A (作者): 生成文章
Agent B (评审): 评估质量，给出反馈
Agent A (作者): 根据反馈修改
Agent B (评审): 再次评估
... 直到通过
```

优势：评审角色可以有不同的关注点（事实性、风格、安全性）。

## 6. 停止条件

| 条件 | 说明 |
|------|------|
| 质量达标 | 自评分数 >= 阈值 |
| 最大轮次 | 防止无限循环 |
| 无改进 | 连续两轮分数不提升 |
| 成本预算 | Token 消耗达上限 |

## 7. 性能与成本权衡

| 维度 | 单次生成 | 3 轮反思 |
|------|---------|---------|
| 延迟 | 2-3s | 6-10s |
| 成本 | 1x | 3-4x |
| 质量 | 基线 | +20-40% |

适用场景：对质量要求高、对延迟容忍度高的任务（报告生成、代码审查）。

## 8. 应用场景

| 场景 | 反思维度 |
|------|---------|
| 代码生成 | 正确性、效率、可读性 |
| 文章写作 | 逻辑、流畅、深度 |
| 翻译 | 准确性、自然度 |
| 数据分析 | 结论是否有数据支撑 |
